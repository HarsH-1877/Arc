1. PRODUCT VISION
================================================================================

Arc is a competitive programming analytics platform that unifies Codeforces and
LeetCode stats into one dashboard, enables head-to-head friend comparisons,
tracks cross-platform streaks, and surfaces topic-level strengths/weaknesses.

Target user: competitive programmers who split time across CF + LC and want
one place to see progress, compare with friends, and stay motivated.

Core user journeys:
  A. Sign up → connect CF/LC handles → view unified dashboard
  B. Add friends → compare ratings, topics, consistency
  C. Maintain streak by solving on either platform
  D. Manage profile, connections, notifications, account security

2. TECH STACK (CURRENT)
================================================================================

Frontend:
  - Next.js 14.2.5 (App Router), React 18, TypeScript
  - Tailwind CSS + custom design tokens (globals.css)
  - Framer Motion, GSAP + ScrollTrigger (landing animations)
  - Recharts (rating charts, radar)
  - TanStack Query (data fetching)
  - Zustand (minimal UI state)
  - Sonner (toasts)

Auth (intended production):
  - Firebase Auth: Google, GitHub, Email/Password
  - Server session via POST /api/auth/session → arc-session HTTP-only cookie
  - Firebase Admin SDK on server (src/lib/firebase/server.ts)

Database (intended production):
  - Neon PostgreSQL + Prisma ORM (prisma/schema.prisma)
  - User handles DB sync themselves — schema is ready

Cache / Jobs (optional, partially wired):
  - Upstash Redis / ioredis (src/lib/redis.ts)
  - BullMQ (package.json) — sync worker exists but queue not fully connected

REMOVED from original spec (by user request):
  - Cloudinary (avatar upload) — avatars from Firebase OAuth or UI Avatars
  - Resend / weekly digest email — in-app notifications only

Mock development mode:
  - USE_MOCK_DATA=true OR NEXT_PUBLIC_USE_MOCK_DATA=true
  - Bypasses auth middleware, serves static mock payloads from src/lib/mock/
  - User can explore full UI without Neon/Firebase configured

6. MOCK DATA MODE — HOW IT WORKS
================================================================================

Enable:
  USE_MOCK_DATA=true
  NEXT_PUBLIC_USE_MOCK_DATA=true

Behavior:
  - middleware.ts: skips auth redirects
  - (app)/layout.tsx: skips session/onboarding checks
  - These API routes return mock data when USE_MOCK_DATA:
      /api/dashboard
      /api/compare/[friendId]
      /api/friends, /api/friends/search, /api/friends/requests
      /api/user/profile
      /api/notifications
  - Mock user: arcdev (arc.dev@example.com) in src/lib/mock/data.ts
  - Mock friends: tourist, benq, etc. for compare/search

To switch to production data:
  1. Set USE_MOCK_DATA=false
  2. Configure DATABASE_URL + DIRECT_URL (Neon)
  3. Configure Firebase env vars
  4. pnpm db:push (or db:migrate)
  5. Sign in via Firebase → session cookie → real API routes hit Prisma
